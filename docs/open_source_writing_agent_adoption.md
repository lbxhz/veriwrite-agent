# 开源写作 Agent 借鉴与 VeriWrite 演进路线

## 决策原则

VeriWrite 不再只依赖项目内试错。每次较大的工作流改造先做三件事：确认用户问题、检索同类开源实现、决定“直接采用、吸收设计、暂不采用”。借鉴重点是已经被实践验证的任务分解和评测方法；DOI、PDF 身份、证据范围、引用绑定、检查点和最终合规仍由 VeriWrite 的确定性合同负责。

## 参考项目与可吸收设计

| 项目 | 已验证的设计 | VeriWrite 对应落点 | 采用方式 |
|---|---|---|---|
| [STORM](https://github.com/stanford-oval/storm) | 先研究与提纲，再按提纲写作；研究问题由多视角对话展开；提纲、正文、润色是独立模块 | V0.2 问题蓝图、V0.4 问题驱动提纲、章节编辑器 | 吸收模块边界与多视角提问，不把其输出直接视为可交付论文 |
| [PaperQA2](https://github.com/future-house/paper-qa) | 搜索、证据收集、重排、回答分离；支持不同角色使用不同 LLM；元数据有冗余来源 | V0.2 相关性闸门、V0.3 证据卡、Writer/Reviewer 独立模型配置 | 优先吸收证据重排和角色模型分离；保留现有本地数据合同 |
| [GPT Researcher](https://github.com/assafelovic/gpt-researcher) | 将任务拆为问题，分别检索、过滤和汇总；多 Agent 有清晰角色；提供过程进度与追踪 | 检索缺口补搜、连续写作事件、可观察性 | 吸收任务分解和进度事件，不立即引入整套编排框架 |
| [AutoSurvey](https://github.com/AutoSurveys/AutoSurvey) | 章节数、长度、检索规模等可配置；生成与独立评测分离 | 写作预算、独立审稿、金标准评分集 | 吸收参数化实验和单独评测入口 |
| [SurveyGen-I](https://github.com/SurveyGens/SurveyGen-I) | 动态计划、记忆辅助写作、章节后与全文后的分层修订 | 定点段落返修、后续的提纲变更影响分析 | 先吸收思想；项目较新，不作为运行时依赖 |

## 结果评价项目与采用结论

| 项目 | 评价方法 | VeriWrite 采用结论 |
|---|---|---|
| [ResearcherBench](https://github.com/GAIR-NLP/ResearcherBench) | 将回答拆成主张，分别评价引文支持与引用覆盖，并以专家 rubric 评价内容覆盖 | 分开计算“证据是否支持主张”和“需要引用的主张是否都有引用”；不能只统计 DOI 数量 |
| [ScholarQABench](https://github.com/AkariAsai/ScholarQABench) | 组合正确性、覆盖度、引用准确性、相关性、组织性等指标 | 质量必须是多维向量，不能用一个引用合规率代表论文质量 |
| [OpenScholar ExpertEval](https://github.com/AkariAsai/OpenScholar_ExpertEval) | 同题结果匿名成对比较，并记录专家偏好 | 后续金标准采用盲评；系统分只用于筛查和版本趋势，不冒充专家评分 |
| [DeepResearch Bench II](https://github.com/imlrz/DeepResearch-Bench-II) | 以原子 rubric 分别评价信息召回、分析推理和表达呈现，并要求给出判分证据 | 把“材料找全”“是否形成分析”“写得是否清楚”拆开，评分依据必须可查看 |
| [LiveDRBench](https://github.com/microsoft/livedrbench) | 对可验证主张计算 precision、recall、F1，同时明确其不覆盖长报告写作的全部质量 | 主张级 F1 适合事实审计，但不能替代结构、语言和论证质量评价 |
| [Open Deep Research](https://github.com/langchain-ai/open_deep_research) | 报告任务得分的同时记录 token 与成本 | 质量、耗时、调用次数、token 和成本应并列记录，不能单独追求少调用 |

VeriWrite 当前实现 `deterministic-proxy-v1` 六维评分：要求符合度 20%、参考文献完整性 15%、证据可追溯性 20%、主题相关性 15%、分析与综合 20%、结构与表达 10%。硬性合规门禁独立于总分；有阻塞项时，即使综合分较高也不能交付。每次论文正文指纹变化时保留上一版评分，并显示总分与各维度差值。

量化结果统一按 `总分 = Σ(维度分 × 权重)` 计算，并同时报告：0–100 总分、等级、六维原始分、相对上一版的维度差值、硬门禁状态与判分依据。任何版本比较都必须固定题目、RequirementSpec、文献约束和评分器版本；否则只展示各自分数，不宣称性能提升。

这套分数的用途是同一题目、同一要求下的回归比较，不用于跨学科排名。逐句语义蕴含、专家 rubric 得分和盲评偏好尚未完成，因此界面会明确显示代理指标的局限。

## 本轮已经采用

1. 新增连续章节状态机：一次授权后顺序处理未确认章节。
2. Writer 与 Reviewer 使用两个独立会话，并允许通过 `LLM_REVIEWER_MODEL` 单独配置审稿模型。
3. 每章执行“生成—整章审稿—问题段落定向重写—复审”。审稿通过且确定性门禁无阻塞时才自动采用并进入下一章。
4. 审稿或修订仍有问题时停在具体章节，不重新生成已经通过的章节，也不重写无问题段落。
5. 章节草稿持久化审稿状态、累计轮数和最近审稿时间；界面持续写入检查点并显示进度。
6. V0.2 改为配额驱动的渐进检索：首轮候选规模随目标文献数变化，筛选后只补搜缺口主题；各检索词使用不重叠的分页窗口并持久化查询深度，避免每轮从 Crossref 第一页重新开始。
7. V0.4 证据型阻塞升级为自动恢复事务：识别缺口研究问题，回退到已有已验证文献或定向补搜，重建证据与提纲后仅失效受影响章节；恢复轮数有上限，避免无限调用。补搜会把上一轮候选、DOI/RIS 验证和相关性评分缓存播种到新运行，只检索新增问题词，并记录已确认无法取得全文的 DOI，避免反复要求同一文件。若证据已充足但审稿仍重复失败，系统把审稿意见写回规划器，重构受影响章节；若补证和重构均无法形成足够证据，则自动把不可证明的细节主张收缩为元数据允许的一般背景，再交给独立审稿复核，而不是继续盲目生成或把内部异常交给用户。
8. 最终交付新增六维质量评分卡、硬门禁状态、评分依据、JSON 导出和同题版本差值。
9. 采用 STORM 的独立 polishing 边界与 SurveyGen-I 的章节后/全文后分层修订：正文完成后新增独立全文结构审稿，检查跨章节重复、章节职责重叠、超长段落和综述错误认领原研究；最终组成部分再由第二次全文编辑调用对照全部正文重构。摘要、引言、现状分析分别具有独立内容合同，模型不能再用正文首段复制补齐结构。高置信正文问题会映射回原章节和段落，沿用原证据包定点返修，不授权全文编辑器修改 DOI、引用键或页码。

## 接下来应做，而不是立即引入大型框架

1. 为 V0.2 增加可解释的文献准入重排：每篇来源必须回答“支持哪个研究问题、允许进入哪一节、删除后哪个主张失去证据”。
2. 把每次检索、写作、审稿、返修记录为统一事件日志，计算耗时、模型、调用次数、失败类型和缓存命中率。
3. 建立人工金标准评分集，将主题聚焦、段落推进、中文自然度、证据蕴含和引用准确性分开评分，并校准当前代理分权重。
4. 允许 Reviewer 输出结构化严重度和通过结论；只有高置信问题触发自动返修，低置信意见保留给用户。
5. 在动态改提纲时执行影响分析：只失效引用范围或中心论点变化的章节，不清空整个 V0.4。

## 暂不采用

- 暂不把 LangChain、LangGraph 或其他完整 Agent 框架引入主链路。当前状态机规模有限，引入大型运行时会增加迁移、调试和恢复成本，却不会自动改善论文质量。
- 暂不让多 Agent 自由修改 DOI、证据卡、引用键和 PDF 页码。多 Agent 只扩展语义推理，可靠性边界仍由代码掌握。
- 暂不以“调用次数少”作为优化目标。优先减少用户点击、整章返工和错误暴露；低价模型调用可用于独立审稿、定点修订和评测。
