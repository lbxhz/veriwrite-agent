# V0.4/V0.5 写作 Agent 循环

## 目标

V0.4/V0.5 不再把“重新生成”当作统一异常处理。每次执行必须经过：

    Plan → Execute → Critic → Controller
      ↑                            │
      └──── 定点返修或有界回退 ────┘

LLM 负责语义规划、正文组织和独立审稿；代码负责证据权限、行动审批、状态转换、
幂等复用、检查点和循环上限。

## V0.4 决策表

| Critic 结果 | Controller 行动 | 保留内容 |
|---|---|---|
| 章节通过 | 进入全文编辑 | 全部已通过章节 |
| 临时生成/审稿异常 | 重试失败章节，最多 3 轮 | 已有草稿和其他章节 |
| 明确问题段落 | 只重写指定段落 | 其他段落和章节 |
| 同类问题连续返修仍失败 | 重构该章论点与证据分配 | 其他已通过章节 |
| 缺少指定 DOI 全文 | 回退 V0.3 获取/扫描全文 | 全部正文检查点 |
| 缺少可用相关论文 | 回退 V0.2 定向补搜并排除重复 DOI | 全部正文检查点 |
| AI 使用政策禁止生成 | 请求用户决定是否改变政策 | 所有产物 |

重复审稿失败被视为“计划或证据错配”，不能继续盲目改写措辞。

## V0.5 决策表

全文编辑器先读取完整正文，检查跨章节重复、章节职责冲突、全局衔接、超长段落和
综述作者错误冒充原论文作者：

- 通过：生成摘要、引言、结论和最终结构；
- 不通过：只重开编辑器定位的章节与段落；
- 最终合规审计发现上游问题：回退到最早负责阶段；
- 全部内部门禁通过：只请求一次最终用户确认；
- 用户确认：Controller 才能产生 finish 决策。

## 持久化

每个 AI 全托管项目拥有独立 run_id。事件写入：

    runtime/agent_runs/<run_id>/

其中包括 Action、Observation、CriticReport、ControllerDecision 和父子检查点链。
Streamlit session_state 只保存 run_id，不承载完整事件历史。刷新后可以从最后一个
连续有效检查点恢复；相同输入和行动的成功 Observation 会直接复用，避免重复模型
调用。

## 当前边界

- V0.4 默认只提供一次“开始生成论文”授权；写作计划确认、逐章生成、审稿、
  定点返修和进入 V0.5 均由 Agent 自动推进；
- 页面只读展示当前阶段、章节进度、最近 Controller 判断、回退原因和检查点，
  内部逐章确认与调试控制不再要求普通用户操作；
- V0.5 自动执行独立全文编辑、最终结构生成、合规审计和内部质量评分，只有
  付费 PDF 无法自动获取、关键政策冲突和最终成品冻结仍请求用户；
- 外部评分 MCP 尚未接入，后续只作为 Critic 的一项输入，不能直接改正文或决定
  是否交付；
- V0.2/V0.3 仍使用现有执行器，但现在可以接收 Controller 的定向回退行动。

## 当前检索增强边界

系统已有证据约束型检索生成，但不是 embedding + 向量数据库方案。V0.3 先完整
提取 PDF，再用确定性词项评分选择候选页，LLM 从候选页生成证据卡；V0.4 根据
已确认提纲把证据卡和来源缩减为章节包、段落包后交给 Writer。代码验证 DOI、
证据卡 ID、PDF 页码和引用权限。该方案属于结构化 Evidence RAG；当前没有
FAISS、Chroma、向量数据库或语义向量 top-k 检索。
