# VeriWrite MVP 低负担交互原则

## 问题判断

原 MVP 的可靠性机制是必要的，但界面把内部审计字段直接变成了用户任务。典型表现是：

- 多个阶段重复要求填写“确认人”和“确认说明”；
- 同一次决定同时要求勾选声明和点击确认按钮；
- JSON、候选池倍率、运行目录和审计包长期占据主界面；
- 已完成阶段仍展示扫描、生成和确认控件；
- 最终论文要求用户确认，却没有先提供论文预览或拒绝路径。

这些操作没有增加系统可靠性。可靠性来自数据合同、状态机、来源验证、引用绑定和审计，
而不是来自更多复选框。

## 门禁规则

只有满足以下任一条件时，主路径才保留人工动作：

1. 需要解决语义冲突或补充会改变下游策略的字段；
2. 即将触发外部检索、模型调用或其他有成本的动作；
3. 用户需要接受可见的章节内容或最终交付物；
4. 操作会清空项目或使已有结果失效。

其他字段由确定性代码记录。操作者沿用上游已确认身份，技术 JSON、诊断和导出放在折叠区。

## 优化后的主路径

| 阶段 | 用户主任务 | 保留的人工决定 | 自动完成或折叠的内容 |
| --- | --- | --- | --- |
| V0.1 | 上传文件或粘贴要求 | 主题、语言、引用格式、字数口径、真实冲突 | 确认人、逐条 warning 勾选、双路明细、审查 JSON |
| V0.2 | 查看检索方案 | “采用方案并开始检索” | 确认人、说明、额外同意框；规模参数进入高级区 |
| V0.3 | 下载核心 PDF | 采用无阻塞的证据与章节覆盖 | 默认核心论文选择、证据与 PDF 审计进入详情区 |
| V0.4 | 核对证据写作计划并审阅章节 | 写作计划一次确认；每章一次“采用并继续” | 逐卡确认、确认人、额外核对框、自动切换与段落检查点 |
| 最终交付 | 预览完整论文 | 确认当前论文或重新生成组成部分 | 最终确认人、额外核对框；无要求时隐藏 AI 声明输入 |

## 界面状态原则

- 每个页面只突出一个当前动作；
- 已完成阶段优先展示结果摘要和下一步，历史操作放入详情区；
- 默认值必须可解释、可修改，并写入最终数据合同；
- 失败信息说明“哪些成果已保存”和“用户下一步做什么”；
- 主界面使用用户语言，版本号和数据合同名只作为辅助信息。

这些变化不放松后端门禁：未确认的检索方案仍不能联网，存在证据缺口的 V0.3 仍不能交接，
存在引用阻塞的章节仍不能采用，最终审计有阻塞时仍不能解锁交付文件。
