# V0.4：证据约束的逐章写作

## 目标

V0.4把V0.3确认的需求、大纲和证据库转化为可审计的分章节草稿。它解决的不是“让
LLM一次写完论文”，而是控制三个业务风险：

1. 模型引用不存在或未经验证的论文；
2. 元数据级文献被用于支撑具体数值、方法和结论；
3. 课程明确禁止AI代写时，系统仍然调用模型生成正文。

## 工作流

```text
V04WritingHandoff
    -> SectionEvidencePacketBuilder
       -> 本章A级全文证据卡
       -> 本章B级辅助来源
       -> 本章C级背景来源
       -> AI使用政策门禁
    -> 用户选择一个章节
    -> LLMGroundedSectionWriter
       -> 只生成段落正文
       -> 声明每段使用的 evidence_card_ids / source_dois
       -> 无权生成最终引用
    -> GroundedSectionDraftService
       -> 检查证据是否属于本章
       -> 检查来源等级是否允许该用途
       -> 由代码生成引用键、DOI和PDF页码
    -> 用户逐章确认
    -> 所有正文章节确认后汇总Markdown与引用审计包
    -> 后续生成摘要、关键词、结论和最终参考文献
```

## 数据合同

- `SectionEvidencePacket`：一个章节可使用的全部证据和来源权限；
- `DraftParagraphProposal`：LLM生成的段落及其支持来源声明；
- `CitationBinding`：程序生成的章节、段落、引用键、DOI、证据卡和页码映射；
- `SectionDraft`：经过确定性审计的章节草稿；
- `V04WritingProject`：各章节的待生成、待确认、阻塞或已确认状态；
- `BodyDraftPackage`：全部确认后的正文Markdown与引用审计轨迹。

## 文献权限

| 证据等级 | 系统允许的用途 |
|---|---|
| A core | 已验证全文和证据卡，可支撑具体方法、结果、限制和详细论断 |
| B supporting | 已验证元数据，可用于一般章节支持；详细论断必须补读全文 |
| C background | 只用于背景、定义和轻量语境，不承担核心结论 |

DOI真实不等于详细论断正确。V0.4只有在证据卡能够回到PDF页码和短原文时，才允许
把该来源用于`detailed_evidence`段落。

## AI政策门禁

确认版`RequirementSpec.ai_policy`是运行时合同的一部分。当课程要求包含“禁止AI生成
句子、段落、正文、代写或洗稿”等规则时：

- 服务层在调用DeepSeek之前停止；
- 控制台仍允许导出章节证据包；
- 用户自行写作，系统只提供真实文献、证据结论和页码；
- 不提供绕过按钮。

这不是技术故障，而是方案的合规降级模式。

## MVP验收标准

- 未确认的V0.3证据库不能进入写作；
- LLM返回值必须通过Pydantic合同；
- LLM引用本章之外的证据卡或DOI时，章节进入阻塞状态；
- B/C级来源不能越权支撑详细论断；
- 模型自行插入DOI或Pandoc引用标记时，章节进入阻塞状态；
- 最终引用标记只能由代码从真实记录生成；
- 每章必须由用户确认；
- 只有全部正文章节确认后才能汇总正文；
- 摘要和结论不在正文完成前生成。

## 当前边界

V0.4.0先完成正文章节闭环。下一步再补充：

- 基于确认正文生成摘要、关键词和结论；
- 按课程要求生成最终参考文献格式；
- 跨章节重复、论证连贯性和引用覆盖审计；
- 对用户修改后的正文重新做主张级证据检查；
- Markdown到DOCX/PDF的排版交付。
